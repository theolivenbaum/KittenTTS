# CLAUDE.md

Guidance for Claude Code (and other contributors) working in this repository.

## Goal

Port KittenTTS to C# (.NET 11): pure managed inference with no Python and no ONNX Runtime, numerically equivalent to the
original implementation, published as NuGet packages (the `KittenTTSSharp` library plus one package per set of model
weights). The original Python implementation lives in `.reference/` and is the reference for every behaviour.

Status: the KittenTTS 2 nano / pico / mini models (StyleTTS 2 / iSTFTNet) are ported, with the English front end and
the espeak front end for the other languages. Still to port: the 1.7B KittenTTS 2 language model with its s3gen vocoder
and voice cloning (`.reference/kittenml/kittentts2/`), the 0.8 ONNX models (`.reference/kittenml/kittentts_legacy/`),
the int4 graphs (obfuscated names), Japanese.

## Layout

- `src/KittenTTS/` — the library (NuGet package `KittenTTSSharp`, namespace `KittenTTS`): `KittenTts` (public API),
  `Model/` (the network), `Numerics/` (GEMM, worker pool, SIMD; copied from curiosity-ai/parakeet), `IO/`
  (safetensors, int8 ONNX graphs, npz, downloader), `Audio/` (STFT, WAV), `Text/` (front ends; `Text/English/Data`
  holds embedded data exported by `scripts/export_english_data.py`).
- `src/KittenTTS.Cli/` — the `kitten-tts` tool (`say`, `phonemize`, `voices`, `download`, `bench`).
- `models/` — `KittenTTSSharp.Models.csproj`, packed once per model / language (`-p:ModelFamily=nano -p:ModelLanguage=en`);
  downloads the pinned Hugging Face revision at pack time. Not in the solution (building it downloads weights).
- `tests/KittenTTS.Tests/` — xUnit: parity with PyTorch / ONNX Runtime (need the environment below), front-end parity
  against `testdata/*.json`, normalization.
- `scripts/` — `torch_reference.py` (PyTorch + ONNX Runtime stage dumps), `english_reference.py` and
  `frontend_reference.py` (front-end references), `export_english_data.py` (embedded data), `gen_kernels.py`.
- `.devops/azure-pipelines.yml` — Azure DevOps CI: build, test, pack `KittenTTSSharp` (CalVer `yy.M.<buildId>`), push on
  `master`; the `publishModelPackages` parameter also packs and pushes the 17 weight packages.
- `.reference/` — the original Python implementation, kept read-only as the reference. Its GitHub workflow is disabled
  (`.github/workflows/*.disabled`); do not re-enable it.

## Build and test

```bash
dotnet build KittenTTS.slnx -c Release
dotnet test tests/KittenTTS.Tests -c Release
```

Model tests need `KITTENTTS_MODEL_DIR` (a local `kitten-tts-2-*` repository) and `KITTENTTS_REFERENCE_DIR` (the output of
`scripts/torch_reference.py --onnx` for that repository); without them they print `SKIPPED` and pass. Run them with a
nano (or pico) and the mini repository after changing numerics. The phoneme test needs `KITTENTTS_MODEL_DIR` only. The
espeak string tests compare only against the espeak-ng build the reference was made with (1.52, espeakng_loader's):
set `KITTENTTS_ESPEAK_LIBRARY` and `ESPEAK_DATA_PATH` to it.

## Rules

- Results must stay numerically equivalent to the reference: float32 weights to PyTorch, int8 weights to ONNX Runtime
  with basic graph optimizations. Stages up to F0 / energy agree to ~1e-6 and durations must be identical; see the
  `ParityTests` summary for why the waveform bounds are looser. Approximations belong behind an option, never in the
  default path.
- Where the reference's arithmetic is ill-conditioned (the sine source's phase), repeat its exact operation order
  (double-accumulated cumsum, `fma` interpolation for PyTorch, separate ops for ONNX); check with the decoder-only test.
- Front-end changes must keep `NormalizerMatchesPython` and `TokenizerMatchesSpacy` at 100% and must not lower the
  phoneme match rate; regenerate references with the scripts rather than editing the JSON by hand.
- Never depend on ICU: use `UnicodeNormalizer` instead of `string.Normalize` (apps may run with InvariantGlobalization).
- The unrolled micro-kernels in `Numerics/Gemm.cs` (`Kernel512R1..12`) are generated by `scripts/gen_kernels.py`; edit
  the generator, paste its output, and re-check the JIT output (`DOTNET_JitDisasm=<method>`) for register spills.
- Measure performance with `kitten-tts bench` (medians; `KITTENTTS_PROFILE=1` for a per-stage breakdown); single runs
  on a shared machine vary by ±15%.
- Gate commits on a successful build and test run.
